## 2. Broken / Misleading Controls Check

- **Result:** **Zero fake/dead buttons exist.** Every visible button in `App.tsx`, `PreviewStage.tsx`, and `DoctorBar.tsx` is wired to real working logic or real Tauri backend calls.
- **Hidden UX Traps / Edge Friction Found:**
  1. **Stale Project Manifest Confusion Across Sessions:** Deleting or editing files externally via OpenCode MCP works in SQLite/disk (`animforge.db`), but `animforge-desktop` only fetches `project_list` once on mount (plus right after `createProject`). There is **no manual Refresh button or workspace file-watcher event** to reload projects created/modified by OpenCode MCP while the desktop window is open!
  2. **No Unsaved-Changes Indicator or Confirmation:** Switching projects or tabs silently discards unsaved `sceneTitleInput` edits (`App.tsx:107-119`), and `Save Scene` does not show dirty state or keyboard `Cmd/Ctrl+S` binding.
  3. **Duplicate / Unused `Scene` Payload Over-Fetching:** `App.tsx` holds full `characters`, `assets`, `storyboard`, `timeline`, and `cameraMoves` in memory (`ProjectDetail`), yet exposes none of them except `scenes[].{id,title,duration,description}`.
  4. **Stage-to-Output Path Opacity:** After `Render MP4` succeeds, `result.videoPath` is returned by `project_render` to `useStudio.ts:330` and then **discarded** cleanly without showing the file path on disk or letting the user open it in Finder/Files.
